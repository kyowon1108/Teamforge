## 1. 해외 시장 — 주요 포스트 분석

### 1.1 Builder.io — "AI 코딩은 싱글 플레이어, 소프트웨어는 팀이 만든다"

**출처**: Steve Sewell (CEO, Builder.io) · 반응 476 · 댓글 81 · 퍼온글 60
**핵심 주장**: 현재 모든 AI 코딩 도구(Claude Code, Cursor, Codex)는 1인용. 소프트웨어는 팀으로 만드는데, 도구가 이를 지원하지 않는다.

**Builder 2.0이 해결하려는 문제**:
- Claude Code/Cursor/Codex에서 브랜치를 푸시하면, 디자이너가 UI를 고치고 PM이 요구사항을 조정 — 엔지니어 재호출 없이
- Slack에서 @Builder 태그 → 스레드 읽고 브랜치 생성 → 빌드 시작
- 실시간 협업: PM이 빌드, 디자이너가 디자인 시스템 기반 수정, 엔지니어가 리뷰 — 병렬 작업
- AI 리뷰 에이전트가 보안/스타일/성능 이슈를 자동 감지

**투자 규모**: $67M 시리즈

**시사점**: 바이브코딩 도구의 가장 큰 갭은 **팀 협업**이며, 이 문제를 해결하는 것만으로 $67M 투자가 가능한 시장.

### 1.2 Postman CEO 인터뷰 — "PM이 PRD 대신 프로토타입을 만든다"

**출처**: Aakash Gupta (PM 전문가) · 반응 435 · 댓글 50 · 퍼온글 18
**인용**: Postman CEO Abhinav (30M+ 개발자 플랫폼)

**현재 변화**:
- PM이 Claude에서 API를 직접 프로토타이핑 → "아이디어 → 동작물" 피드백 루프가 **주 단위 → 시간 단위**로 단축
- 디자이너가 Cursor로 직접 PR 전송 → 디자인-프로덕션 핸드오프 갭에서 **제품 품질 30%가 손실**되던 문제 해소
- Staff 엔지니어가 높은 자율성으로 프로젝트를 리드 → PM의 새로운 파트너

**새 PM 스킬셋**:
1. Taste (심미안)
2. Technical instinct (기술 감각)
3. 프로토타입 능력 (학습 가능한 수준의 결과물)

**시사점**: PRD 시대의 종말. PM/디자이너가 코드에 직접 기여하는 것이 표준이 되고 있으며, 이를 가능하게 하는 도구가 필요하다.

### 1.3 CTO 관점 — "비개발자가 만든 앱, 어디서 운영할 것인가?"

**출처**: Fabian Wesner (CTO) · 반응 78 · 댓글 30 · 퍼온글 3

**문제 인식**:
- 코딩 에이전트 덕분에 조직 전반에서 비개발자가 앱을 만들고 있음
- **Shadow IT 위험**: 비개발자가 개인 Vercel/Netlify 계정으로 비즈니스 크리티컬 앱 배포
- 비개발자가 간과하는 영역: 모니터링, 인증(SSO/LDAP), GDPR, 시크릿 관리, 백업, 배포 파이프라인

**제안하는 솔루션 — 회사 PaaS**:
- 호스팅 인프라
- 보안/컴플라이언스 가드레일
- 기업 ID 템플릿
- LLM 키 관리 (OpenRouter 등)
- 코딩 에이전트 라이선스 (Claude Code, Codex)
- 도메인 관리 (서브도메인, SSL)
- 앱 레지스트리 (중복 앱 방지)
- 사용량 모니터링 + 비용 투명성

**시사점**: 바이브코딩이 보편화되면 **거버넌스 문제**가 핵심 과제가 된다. "만드는 것"보다 "운영하는 것"이 더 큰 도전.

### 1.4 비개발자의 생산성 폭발 — "마케터가 24시간에 비디오 에디터 구축"

**출처**: Apoorv Sarawgi (AI Engineer)

**사례**: 마케팅 팀원이 LTX2 모델로 24시간 만에 프로급 비선형 비디오 에디터(Adobe Premiere급) 구축

**관찰**:
- "how는 AI가 처리, what은 창작자가 정의" — 소프트웨어 개발 진입 장벽 공식 붕괴
- 로컬 실행(ComfyUI 등)으로 API 비용 제로 → 실험 마찰 제거
- 오픈소스 vs 프로프라이어터리: 연구급 코드베이스가 공개되면서 "위에 빌드" 가능

**개발자에게 던지는 질문**: "비개발자가 24시간에 에디터를 만들 수 있다면, 당신의 기초 지식과 아키텍처 이해로 무엇을 만들고 있는가?"
